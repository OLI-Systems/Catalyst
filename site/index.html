Choose AI

Pick a repo, pick an agent.

Selecting a repository shows you what you're walking into before you start: the branch, whether the tree is clean, how many branches and open PRs it has, and how recent the commits are.

  • Claude Code, Codex and Gemini CLI, detected on your PATH
  • Stack read from the repo — Node, .NET, Python, Rust, Go, React
  • Optional worktree isolation, so your main checkout stays untouched

Additional repos

Hand it more than one repo.

The card you clicked is the primary repo — the agent's working directory. Alongside it you can pick any of the others under the same root, which is how a change to an API and the dashboard that calls it happens in one session instead of two.

Catalyst hands each agent the extra repositories the way that agent expects, so they arrive as real working directories rather than paths pasted into a prompt.

Claude and Gemini treat them as additional places they are allowed to read and edit. Codex works differently — it stays focused on the primary repository, and the most Catalyst can do is let it write to the others. So multi-repo is genuinely weaker there, and it would be misleading to claim otherwise.

Sessions

It shows you what's already there.

Pick an agent for a repo you have worked in before and Catalyst doesn't quietly start a second one. It asks what already exists and lists it: sessions running right now, and past conversations that CLI can resume. Starting fresh is still one click — it is just no longer the only option.

  • Switch to a session that is already running, worktree and all
  • Resume a past conversation, labelled with how it started
  • Delete one conversation — the name is quoted back before it goes
  • Nothing to offer? The dialog never appears and the launch is one click

Session

Real terminals, not a chat box.

Catalyst doesn't wrap or re-implement any AI. It runs the real tool in a real terminal, so everything the agent can normally do, it still does — prompts, slash commands, permission requests, colour and all.

  • One tab per session, up to eight, plus inner split terminals
  • Paste an image straight into the terminal
  • Branch, diff and changed files in the panel beside it
  • Pull, push and PR without leaving the session

Settings

Set up once, on your machine.

Catalyst runs entirely on localhost. Your code never leaves the machine, and access tokens go to the OS credential store — Windows Credential Manager or the macOS Keychain — not to a config file.

  • One root folder, scanned for git repositories
  • Azure DevOps work items: fetch a task, start it, set it in progress
  • Install a missing CLI from inside the app
  • Reset wipes cached data and both tokens in one action

Updates

It keeps itself current.

Catalyst checks GitHub Releases when it starts. When there's a newer build it offers it, and installs it when you say so.

Every release is signed, and the app verifies that signature before it installs anything. Settings → Updates shows the installed version and checks again whenever you ask.

Privacy

Your code stays on your machine.

Catalyst is a local application, not a service. There is no Catalyst account, no server to sign in to, and no telemetry. It runs an HTTP and WebSocket server bound to localhost and talks to nothing else.

  • No account, no telemetry

    Nothing to sign up for and nothing phoned home. Catalyst itself makes no network calls except to check GitHub for a new release.

  • Tokens in the OS keystore

    Access tokens go to Windows Credential Manager or the macOS Keychain — never a plaintext config file in your home directory.

  • Scoped to one folder

    Catalyst only reaches repositories under the root folder you choose. Paths arriving from the UI are checked against it server-side.

  • Signed updates

    Every release is signed, and the app verifies that signature before it installs anything — so an update has to come from us.

  • Readable end to end

    MIT licensed, no build obfuscation, no minified bundle. If you want to know what it does with your repositories, the source is right there.

  • What Catalyst can't promise

    The agents themselves are online tools. Claude Code, Codex and Gemini send your prompts and code to their own providers under their own terms — Catalyst launches them, it does not proxy or intercept that. Your privacy with the model is between you and whoever makes it.

Install

Get Catalyst.

Windows

Run the installer

The download is a zip holding Catalyst_<version>_x64-setup.exe. Unzip it and run the installer — it installs for the current user, so it never asks for an administrator. Windows may ask you to confirm an app from an unrecognised publisher; see code signing for why.

macOS · Apple Silicon

Open the disk image

Download the disk image and drag Catalyst to your Applications folder. If macOS blocks the first launch, right-click Catalyst and choose Open to get past it — the README has a one-line alternative if you prefer the terminal.

You'll also need: git on your PATH, and at least one agent CLI — Catalyst can install a missing one for you. Node.js ships inside the app, so there's nothing else to set up.

Code signing

What is signed, and what isn't.

Updates are signed

Every release is signed with a key held by the maintainers, and Catalyst verifies that signature before it installs an update. An update that fails verification is refused. This is what protects you from a tampered update.

The installer is not

The Windows installer and the macOS app are not yet signed with an operating-system certificate, which is a separate thing entirely. So Windows may warn about an unrecognised publisher, and macOS may refuse the first launch. Both are reputation warnings, not a sign that anything is wrong with the download.

Built in the open

Every release is built by GitHub Actions from the tagged commit in the public repository — never from a maintainer's machine. You can read the workflow, the source it built, and the log of the build that produced the file you downloaded.

Catalyst collects no telemetry and phones home only to check GitHub for a newer release. We are applying for free open-source code signing so these warnings go away; until then, the download links above serve a zip on Windows, because browsers treat an unsigned installer with suspicion it has not earned.
